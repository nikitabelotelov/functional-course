# Board Game Store (origin)

Учебное CLI-приложение «магазин настольных игр» на TypeScript. Исходная
объектно-ориентированная версия, которая затем переписывается в
функциональном стиле в соседней папке `fp/`. Все данные хранятся только в
памяти процесса — ни базы данных, ни HTTP API, ни GUI нет.

## Что делает приложение

Пользователь работает через интерактивное текстовое меню в терминале:
выбирает или создаёт покупателя, просматривает каталог настольных игр,
собирает корзину, оформляет заказ с учётом скидок, промокодов, доставки и
бонусных баллов, затем может посмотреть историю заказов, изменить статус
заказа или отменить его. Отдельные административные подменю позволяют
управлять каталогом, складом, акциями и посмотреть журнал событий.

## Установка и запуск

```bash
cd origin
npm install

# интерактивный запуск в терминале
npm start

# сборка в dist/ и проверка типов
npm run build
npm run typecheck

# тесты
npm test
```

### Запуск через pipe (неинтерактивный режим)

CLI одинаково работает и в терминале, и при вводе через pipe — это нужно,
чтобы приложение мог проверить скрипт или агент (spec: Уточнения п. 15).
Чтобы `npm` не добавлял в вывод свою служебную шапку, используйте
`--silent` или запускайте `tsx` напрямую:

```bash
printf "5\n3\n1\n0\n2\n2\nG-5\n2\n1\n0\n3\ny\n4\n0\n0\n" | npm start --silent
# или
printf "5\n3\n1\n0\n2\n2\nG-5\n2\n1\n0\n3\ny\n4\n0\n0\n" | npx tsx src/index.ts
```

Сценарий выше: выбрать покупателя Alice, добавить в корзину 2 шт. игры
`G-5` (Azul), посмотреть корзину, оформить заказ без оплаты баллами,
подтвердить, посмотреть список своих заказов, выйти.

В неинтерактивном режиме (когда `stdin` не TTY) введённая строка
повторяется в выводе после приглашения — так лог читается как диалог. При
достижении конца ввода программа печатает `Input ended. Exiting.` и
завершается с кодом 0, не падая со стектрейсом.

## Основные сущности

* **BoardGame** — настольная игра в каталоге (цена, категория, число
  игроков, издатель, активна ли).
* **InventoryItem** — складской остаток конкретной игры: свободное
  количество и зарезервированное под заказы.
* **Customer** — покупатель: уровень лояльности, бонусные баллы, корзина,
  история заказов.
* **ShoppingCart / CartItem** — корзина и её позиции; цена всегда берётся
  из текущей цены игры.
* **Order / OrderItem** — оформленный заказ; цена, скидка и итог по каждой
  позиции фиксируются в момент оформления и не зависят от последующего
  изменения цены в каталоге.
* **Promotion** и подклассы — `CategoryDiscount`, `ProductDiscount`,
  `BulkDiscount`, `LoyaltyDiscount`, `MinOrderAmountDiscount`,
  `PromoCodeDiscount`.

Сервисы: `CatalogService`, `InventoryService`, `CustomerService`,
`PromotionService`, `DeliveryService`, `PricingService`,
`CheckoutService`. Все они собираются в одном месте — классе `Store`
(`src/Store.ts`), который также хранит активного покупателя текущей
сессии.

## Основные пользовательские сценарии

Главное меню:

```text
Active customer: Alice (C-1)
1. Catalog               — обзор, детали, поиск, фильтры
2. Cart                  — просмотр, добавление, удаление, изменение количества
3. Checkout              — оформление заказа с баллами и подтверждением
4. My orders              — заказы активного покупателя
5. Customers              — список, создание, выбор активного, инфо, история
6. Inventory management   — остатки, пополнение, резервы (админ)
7. Catalog management     — добавление игр, цена, активность (админ)
8. Promotions             — активные акции, промокоды, предпросмотр скидок
9. Orders management      — все заказы, смена статуса, отмена (админ)
10. Activity log          — журнал событий магазина
0. Exit
```

Типичный путь пользователя: выбрать покупателя (п. 5) → посмотреть каталог
и найти игры (п. 1) → добавить их в корзину (п. 2) → увидеть
предварительную стоимость со скидками (п. 2 → «View cart») → оформить
заказ (п. 3) → увидеть изменение складских остатков (п. 6) → посмотреть
заказ в истории (п. 4) → отменить заказ, если это допустимо, и увидеть
восстановление остатков (п. 9 → «Cancel order»).

## Структура проекта

```text
origin/
  src/
    config/rules.ts       — числовые константы бизнес-правил
    domain/                — BoardGame, Customer, Order, ShoppingCart, ...
    promotions/             — Promotion и 6 подклассов акций
    services/               — Catalog/Inventory/Customer/Promotion/Delivery/Pricing/CheckoutService
    cli/                    — io.ts, Prompter.ts, format.ts, StoreCli.ts, menus/
    data/seed.ts            — повторяемые тестовые данные
    utils/                  — formatMoney, IdGenerator, ActivityLog
    Store.ts                — createStore(): сборка всех зависимостей
    index.ts                — точка входа
  tests/
    domain/, promotions/, services/, utils/ — unit-тесты
    e2e/scenario.test.ts     — сценарий из "Критерия готовности" через StoreCli
  package.json
  tsconfig.json
```
